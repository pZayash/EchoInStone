# Реестр тегов записей памяти

Канонические метки для секции **Теги** в файлах [memory/](memory/).

**Не путать с [CONTEXT.md](CONTEXT.md):** там словарь **домена** (транскрипт,
диаризация, сегмент); здесь — **индекс** (как классифицировать и найти запись).

## Область действия

- Записи в `memory/**`.
- `openspec/**`, `docs/**` — **вне** реестра, если не оговорено.

## Правила

1. **2–6 тегов** на запись; kebab-case, кириллица допустима.
2. **Новый канонический тег** — сначала строка в таблице ниже, затем запись в `memory/`.
3. Не дублировать в тегах длинные определения из `CONTEXT.md` — достаточно короткой
   метки (`ASR`, `diarization`), если нужна фильтрация.
4. Свободные предметные теги без строки в таблице — **допустимы**;
   в таблицу добавляй, если тег повторяется в 3+ записях.

## Канонические теги (тип записи)

| Тег | Назначение | Связь |
| --- | --- | --- |
| **openspec** | Договорённости в /explore или вокруг change | `openspec/changes/` |
| **pipeline** | Порядок шагов capture → processing | orchestrator, pipelines |
| **benchmark** | Сравнение бэкендов, метрики качества/скорости | `benchmark_transcribers.py` |
| **close-chat** | Правила закрытия сессии, sync+archive | `close-chat`, `feedback_openspec` |

## Частые предметные теги (примеры)

`ASR`, `whisper`, `faster-whisper`, `diarization`, `pyannote`, `alignment`,
`youtube`, `podcast`, `ocr`, `scene-detection`, `GPU`, `XPU` — без отдельной
строки в таблице, пока не станут обязательными для классификации.

## Поиск

```bash
rg "whisper" memory/
rg "openspec" memory/
```

Перед нетривиальной задачей: [CONTEXT.md](CONTEXT.md) (если есть) → `memory/` →
активный change в `openspec/changes/`.
