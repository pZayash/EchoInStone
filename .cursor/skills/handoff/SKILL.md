# handoff — передача сессии следующему агенту

Адаптация [mattpocock/skills — handoff](https://github.com/mattpocock/skills/blob/main/skills/productivity/handoff/SKILL.md) (MIT) и [comol/ai_rules_1c](https://github.com/comol/ai_rules_1c/blob/main/content/skills/handoff/SKILL.md) под стек EchoInStone (Python 3.12 / Poetry / pytest-bdd, OpenSpec, `memory/`).

**Принцип:** ссылаться на устойчивые артефакты, не копировать их. Handoff — снимок сессии, не замена OpenSpec и не долговременная память.

## Когда вызывать

- «handoff», «/handoff», «compact session», «лимит контекста».
- «передай контекст», «сохрани для продолжения», «продолжим в новом чате».
- Большая задача не помещается в одну сессию.

## Аргумент

- Путь (`.md` или существующая папка) → **целевой файл**.
- Иначе → **фокус** следующей сессии (в шапку документа).
- Оба: первый токен — путь, остальное — фокус.
- Без аргумента — спросить фокус одной строкой, затем путь по умолчанию.

## Куда писать

1. Каталог: `handoffs/` в корне репозитория (создать, если нет). Каталог в `.gitignore` — локальные снимки сессий, в git не коммитить.
2. Имя по умолчанию: `handoff-YYYYMMDD-HHMMSS.md` (локальное время).
3. Явный путь от пользователя — использовать его (перезапись без лишних вопросов).
4. **Перед записью** прочитать целевой файл через Read. Ожидаемая ошибка «файл не найден» — норма; защита от случайной перезаписи чужого файла.

## Структура документа

Писать **нормальным русским**, не в стиле caveman — следующий агент должен однозначно понять контекст.

Ссылки на файлы — markdown `[text](path)`, относительный путь от корня репозитория (см. [CLAUDE.md](../../../CLAUDE.md)); без wikilinks.

```markdown
# Handoff: <цель сессии одной строкой>

**Когда**: YYYY-MM-DD HH:MM (локальное)
**Ветка / коммит**: <ветка>, <короткий SHA> — <subject> (если есть git)
**Фокус следующей сессии**: <из аргумента, если был>

## Текущее состояние

1–3 предложения: что сделано в конце, что не доделано, что заблокировано.

## Открытые вопросы

Список нерешённых вопросов (архитектура, ожидание пользователя, неясный контракт). Если пусто — раздел опустить.

## Изменённые файлы в этой сессии

- `path/to/file` — что и зачем менялось.

Только diff этой сессии. Если правок не было — раздел опустить.

## Проверки

- **Тесты**: `poetry run pytest` (pytest-bdd) — пройдено / ошибки / не запускалось.
- **Пайплайн**: `echoinstone "<url>"` / `echoinstone-test` — прогон делался / нет; где `results/…/speaker_transcriptions.csv`.
- **OpenSpec**: активное изменение `openspec/changes/<id>/` — статус задач (кратко).

## Следующие шаги

1–5 императивных пунктов с проверяемым результатом.

## Что подгрузить в следующей сессии

- **Навыки**: релевантные из `.cursor/skills/` — `openspec-apply-change`, `openspec-propose`, `explore`, `youtube-video-summary`, `close-chat`, `sandbox-oneliner`.
- **Документация**: `docs/ai/...` по теме (например [echoinstone-cli.md](../../../docs/ai/echoinstone-cli.md)).
- **Память**: `rg "тег или фраза" memory/` / SemanticSearch с фильтром по `memory/`; стабильные правила — [memory.md](../../../memory.md), теги — [TAGS.md](../../../TAGS.md).
- **Поиск по коду**: `rg` / SemanticSearch; узкий grep по `EchoInStone/**`.

## Ссылки (содержимое не копировать)

- [proposal.md](../../../openspec/changes/<id>/proposal.md), design.md, tasks.md
- `openspec/changes/<id>/implementation-notes.md` — если есть (не копировать текст; перед archive файл удаляют)
- Записи в `memory/<имя>.md`
- Коммиты / PR (URL или SHA)
- `git-commit-summary/` — если оттуда брали решения
```

## Чего не писать в handoff

- Полный текст proposal/design/tasks, implementation-notes, ADR, исследований, описания PR/коммита — только ссылки.
- Полный код модулей — путь и краткое описание изменения.
- Секреты, токены, пароли, содержимое `EchoInStone/config_private.py`, HF-токены.
- Содержимое `results/**`, `diarization/**`, медиа, логов.

## После записи

1. Сообщить пользователю относительный путь к файлу и примерный объём (строки).
2. Если в сессии появились **кандидаты в долговременную память** — перечислить отдельно:
   - глобальное, критичное и стабильное → возможно [memory.md](../../../memory.md);
   - рабочий факт / грабли / договорённость → новый или обновлённый файл в `memory/` (теги по [TAGS.md](../../../TAGS.md)).
   Не сохранять в `memory/` автоматически без запроса пользователя.
3. Подсказать навыки для следующей сессии.

## Границы

- Handoff не конфигурация и не код; **не** гонять по нему pytest / линтеры.
- Handoff **не заменяет** OpenSpec: если нужен change, а proposal нет — предложить [openspec-propose](../openspec-propose/SKILL.md) и сослаться на будущий `openspec/changes/<id>/`.
- Handoff **не дублирует** `memory/` и `memory.md` — другой канал (сессия vs долгая память).
- **Коммит в git** — только по явному запросу пользователя или через [close-chat](../close-chat/SKILL.md) (см. [AGENTS.md](../../../AGENTS.md)).
